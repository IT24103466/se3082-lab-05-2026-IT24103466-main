How #pragma omp single works in this program
------------------------------------------------------------------------------
#pragma omp parallel creates a team of threads and every thread executes the parallel
block, so every thread prints "thread # n" and "Hi again from thread # n" (4 or 8 times
each in the outputs above).

The block after #pragma omp single is executed by ONE thread only. The first thread of
the team that reaches the single construct executes it and all the other threads skip it.
So "Inside Single # n" and "Exiting Single" are printed exactly once, not once per
thread, however many threads there are (4 or 8). In both runs the thread that executed
the block was thread 1, because it arrived first. It is not necessarily thread 0 and it
can be a different thread in another run (this is the difference from #pragma omp master,
which always uses thread 0).

There is an implicit barrier at the end of a single construct (unless the nowait clause
is used). The threads that skipped the block wait at the end of it until the executing
thread has finished it and all threads have arrived. The output shows this: no "Hi again"
line is printed before every thread has printed "thread # n" and the single block has
finished; all the "Hi again" lines come after the "Exiting Single" line. The order of
the "Hi again" lines themselves is not fixed, since the threads run concurrently.

Use: single is used for work that must be done only once inside a parallel region, such as
printing a message, reading input or initialising shared data, while still allowing the
other threads to wait until it is complete.
