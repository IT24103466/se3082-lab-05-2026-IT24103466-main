How #pragma omp master works in this program
------------------------------------------------------------------------------
#pragma omp parallel creates a team of threads and every thread executes the parallel
block, so every thread prints "thread # n" and "Hi again from thread # n".

The block after #pragma omp master is executed ONLY by the master thread, which is
always thread number 0, and all the other threads skip it. So "Inside Master # 0" and
"Exiting Master" are printed exactly once, and the number printed is always 0, in every
run and for any number of threads (4 or 8). Compare this with #pragma omp single, where
the thread that runs the block can be any thread (the first to arrive).

There is NO implicit barrier at the start or at the end of a master construct. The
other threads do not wait for the master thread; they go straight on to
"Hi again from thread # n". The output shows this: in the 8 thread run, thread 4 printed
"thread # 4" and "Hi again from thread # 4" BEFORE thread 0 had even printed "thread # 0"
and run its master block, and other threads (7, 5, 2, ...) printed "Hi again" lines while
or after the master block was being run. So "Inside Master" and "Exiting Master" can
appear in the middle of the other threads' output, and the order of the lines changes
from run to run.

If the other threads must wait until the master block is finished, an explicit
#pragma omp barrier has to be placed after it; this is the difference from
#pragma omp single, which has the implicit barrier at the end.

Use: master is used for work that should be done once by thread 0 (for example printing a
progress message or setting a value), when no waiting of the other threads is needed.
