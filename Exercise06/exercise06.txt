Lab 05 - Exercise 6: Element-wise multiplication of two arrays with strip mining

Problem: A[], B[], C[] with N = 1,000,000 doubles;  C[i] = A[i] * B[i]  for i = 0..N-1

Compile and run:
    gcc -O2 -fopenmp strip.c -o strip.o
    OMP_NUM_THREADS=<threads> ./strip.o

------------------------------------------------------------------------------
Code
------------------------------------------------------------------------------
#define N     1000000
#define STRIP 256

double *A = aligned_alloc(64, N * sizeof(double));   /* 64-byte aligned arrays */
double *B = aligned_alloc(64, N * sizeof(double));
double *C = aligned_alloc(64, N * sizeof(double));

#pragma omp parallel for schedule(static)
for (int s = 0; s < N; s += STRIP) {                  /* one iteration = one strip */
    int end = (s + STRIP < N) ? s + STRIP : N;        /* the last strip may be shorter */
    #pragma omp simd
    for (int i = s; i < end; i++)                     /* inner loop works inside a strip */
        C[i] = A[i] * B[i];
}

------------------------------------------------------------------------------
How the three requirements are met
------------------------------------------------------------------------------
1. Strip mining: the single loop over N elements is split into an outer loop over strips
   (s = 0, 256, 512, ...) and an inner loop over the elements of one strip. Each strip
   has a fixed size of STRIP = 256 elements. The last strip is handled with
   end = min(s + STRIP, N) because 1,000,000 is not an exact multiple of 256
   (3906 full strips plus a final strip of 64 elements).

2. OpenMP parallelisation: #pragma omp parallel for schedule(static) on the outer loop
   shares out the strips among the threads. Each thread works on whole strips, so
   different threads write to different parts of C (no data race, no mutex needed, and
   threads rarely touch the same cache line). Inside a strip, the elements are
   independent, so the inner loop is marked with #pragma omp simd.

3. Strip size aligned with the SIMD vector width: a double is 8 bytes, so a 256-bit AVX2
   vector holds 4 doubles and a 512-bit AVX-512 vector holds 8 doubles. 256 elements is a
   multiple of both (64 AVX2 vectors or 32 AVX-512 vectors per strip), so the inner loop
   runs in whole vectors without a scalar remainder loop. 256 doubles = 2048 bytes is also
   a multiple of the 64-byte cache line (32 cache lines per array per strip), and the three
   strips (A, B, C = 6 KB) fit easily in the L1 cache (32 KB). The arrays are allocated
   with 64-byte alignment (aligned_alloc), so each strip starts on a cache-line and vector
   boundary.

------------------------------------------------------------------------------
Results (N = 1,000,000, strip size 256)
------------------------------------------------------------------------------
The program checked every element of C against A[i] * 2.0 (correct = 1 in all runs).

 Threads | Serial time (s) | Parallel time (s) | Speedup
    1    |    0.003920     |    0.002716       |  1.44
    2    |    0.003867     |    0.002084       |  1.86
    4    |    0.003973     |    0.002461       |  1.61
    8    |    0.004664     |    0.002517       |  1.85

------------------------------------------------------------------------------
Discussion
------------------------------------------------------------------------------
- The result is correct for every number of threads, and the strip mined parallel version
  is faster than the serial loop in all runs (speedup 1.4 to 1.9).
- The gain with 1 thread (1.44) does not come from threads; it comes from the strip
  mining and the SIMD loop (vector instructions process several elements per
  instruction, and each strip is worked on while it is in the cache).
- The speedup does not grow beyond about 1.9 when more threads are used. This
  calculation has very little arithmetic per element (one multiplication for 24 bytes
  read and written), so the run time is limited by memory bandwidth, not by the number
  of cores, and the cost of starting the parallel region is comparable to the total time
  (about 2 ms). Using more than the 4 physical cores (8 threads) gives no extra benefit.
- The best use of strip mining and threads is therefore for loops with more computation
  per element, or for much larger arrays than 1,000,000 elements.
